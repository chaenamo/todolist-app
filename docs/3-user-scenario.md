## 1. 개요

### 1.1 목적
PRD 3.1의 화면에서 사용자가 수행하는 **과업 단위 흐름**(기본/대안/예외)을 정의해 화면 설계·테스트 케이스 작성의 기준으로 삼는다.

### 1.2 작성 원칙
- PRD 1.3에 따라 페르소나별 생활 서사 시나리오는 쓰지 않는다. 대상 사용자(학생, 20~50대 직장인)는 맥락 한 줄로만 언급한다.
- MVP(Must) 범위를 중심으로 하고, Should 항목은 우선순위를 표기해 짧게 다룬다.
- 접근성은 범위 제외(NFR-17). 모바일은 반응형 웹만 다룬다(TC-01, NFR-16).
- API·DB·컴포넌트 등 구현 세부는 다루지 않는다(PRD 3.2).
- 공통 전제: 회원가입·로그인 외 모든 시나리오는 BR-01, BR-02를 따른다. 아래 공통 예외는 각 시나리오에서 반복하지 않는다.

## 3. 시나리오 상세

### SC-01 첫 사용: 회원가입

| 항목 | 내용 |
|------|------|
| 관련 | UC-01, FR-01, FR-02 / BR-03, BR-05 |
| 우선순위 | Must |
| 화면 | 로그인 / 회원가입 → 할일 목록 |
| 사전 조건 | 미인증 방문자 |

**기본 흐름**
1. 사용자가 로그인 화면에서 회원가입으로 전환한다 → 시스템이 이메일·비밀번호·이름 입력란을 표시한다.
2. 사용자가 값을 입력하고 가입을 요청한다 → 시스템이 계정을 만들고 '기본' 카테고리를 자동 생성한다(BR-05).
3. 시스템이 자동 로그인 처리 후 할일 목록(빈 상태)으로 이동한다. **(가정, G-01)**
4. 사용자가 카테고리 관리 또는 할일 편집의 카테고리 선택에서 '기본'을 확인한다.

**대안/예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-01-A1 | 자동 로그인을 하지 않기로 결정된 경우(G-01) | 가입 완료 안내 후 로그인 화면으로 이동 → SC-02 |
| SC-01-E1 | 이미 가입된 이메일 | 가입 거부, "이미 사용 중인 이메일" 안내, 입력값 유지 (BR-03) |
| SC-01-E2 | 필수 항목 누락 / 이메일 형식 오류 / 비밀번호 규칙 위반 | 가입 거부, 해당 필드 오류 표시 (비밀번호 규칙은 G-05) |

**사후 조건 / 확인 포인트**
- 사용자 계정 1개와 '기본' 카테고리 정확히 1개가 존재한다(BR-05, 도메인 4.2).
- 비밀번호는 해시로만 저장된다(NFR-09).

### SC-02 로그인 / 로그아웃 / 세션 만료

| 항목 | 내용 |
|------|------|
| 관련 | UC-02, FR-01, A-14 / BR-01, NFR-10 |
| 우선순위 | Must |
| 화면 | 로그인 / 회원가입 |
| 사전 조건 | 가입된 계정 존재 |

**기본 흐름**
1. 사용자가 이메일·비밀번호를 입력하고 로그인한다 → 시스템이 인증 후 access token(15분)과 refresh token(14일)을 발급하고 할일 목록으로 이동한다(NFR-10).
2. 사용 중 access token이 만료되면 → 시스템이 refresh token으로 자동 갱신하고 작업을 이어간다. 사용자에게는 보이지 않는다(NFR-10).
3. 사용자가 로그아웃을 선택한다 → 시스템이 서버에서 refresh token을 폐기하고 클라이언트 토큰을 폐기한 뒤 로그인 화면으로 이동한다(NFR-10, A-14).

**대안/예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-02-A1 | 유효한 refresh token이 남아 있는 상태로 앱 재방문(14일 이내, 로그아웃하지 않음) | 시스템이 refresh token으로 access token을 먼저 발급받은 뒤 로그인 생략, 할일 목록 표시. 갱신 실패 시 로그인 화면 |
| SC-02-E1 | 이메일 미가입 또는 비밀번호 불일치 | 로그인 거부. 어느 쪽이 틀렸는지 구분하지 않는 메시지 표시 (G-04) |
| SC-02-E2 | 세션 만료(refresh token 14일 만료 또는 폐기) 후 작업 시도 | SC-00-E2. 작성 중이던 입력은 보존되지 않을 수 있음 (G-03) |
| SC-02-E3 | 로그아웃 후 브라우저 뒤로 가기로 보호 화면 접근 | SC-00-E1 |

**사후 조건 / 확인 포인트**
- 인증 없는 요청은 401(NFR-10 측정 방법). 로그아웃 후 보호 화면 접근 불가, 로그아웃한 refresh token으로 갱신 불가.

### SC-03 카테고리 등록 (+ 이름 변경·삭제)

| 항목 | 내용 |
|------|------|
| 관련 | UC-04, FR-02, A-13 / BR-06, BR-07, BR-09 |
| 우선순위 | 등록 Must / 이름 변경·삭제 Should (M-05) |
| 화면 | 카테고리 관리 |
| 사전 조건 | 로그인 상태 |

**기본 흐름 (등록, Must)**
1. 사용자가 카테고리 관리 화면에서 이름(예: "업무")을 입력하고 등록한다.
2. 시스템이 앞뒤 공백을 제거한 이름으로 저장하고 목록에 추가한다(BR-07).
3. 새 카테고리가 할일 편집의 카테고리 선택과 목록 필터에 나타난다.

**대안 흐름 (Should)**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-03-A1 | 사용자 카테고리 이름 변경 | BR-07 동일 적용 후 저장. 소속 할일은 그대로 유지 |
| SC-03-A2 | 사용자 카테고리 삭제 | 확인 절차 후 삭제(G-07). 소속 할일은 '기본'으로 이동(BR-09) |

**예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-03-E1 | 공백만 입력 | 거부, "이름을 입력하세요" (BR-07) |
| SC-03-E2 | 사용자 내 중복 이름(" 업무 " 포함, '기본' 포함) | 거부, "이미 있는 이름" (BR-07) |
| SC-03-E3 | '기본' 카테고리 이름 변경·삭제 시도 (Should) | 해당 동작을 노출하지 않거나 거부 (BR-06) |

**사후 조건 / 확인 포인트**
- 카테고리 삭제 후 할일 수 변화 없음, 이동된 할일은 '기본' 소속(BR-09).
- 현재 필터가 삭제된 카테고리였다면 필터 초기화 필요 (G-08).

### SC-04 할일 등록

| 항목 | 내용 |
|------|------|
| 관련 | UC-05, FR-02, FR-04 / BR-08, BR-10, BR-11, BR-12 |
| 우선순위 | Must |
| 화면 | 할일 목록 → 할일 편집(등록) |
| 사전 조건 | 로그인 상태 |

**기본 흐름**
1. 사용자가 할일 목록에서 등록을 선택한다 → 시스템이 빈 할일 편집 화면을 연다.
2. 사용자가 제목, (선택) 설명을 입력한다.
3. 사용자가 날짜 피커로 시작일자·종료일자를 선택한다(FR-04).
4. 사용자가 카테고리를 선택한다(또는 비워 둔다).
5. 사용자가 저장한다 → 시스템이 저장 후 할일 목록으로 돌아가고 새 할일이 정렬 위치(Q-05)에 상태와 함께 표시된다.

**대안/예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-04-A1 | 카테고리 미지정 | '기본' 카테고리에 속함 (BR-08, AC-01) |
| SC-04-A2 | 시작일자 = 종료일자 | 허용, 하루짜리 할일 (BR-11) |
| SC-04-A3 | 과거 날짜 지정 | 허용. 미완료면 즉시 '기한 초과' 등으로 판정 (BR-12, ST-04) |
| SC-04-A4 | 저장 전 취소/이탈 | 저장하지 않고 이전 화면으로. 이탈 확인 여부는 G-02 |
| SC-04-E1 | 제목·시작일자·종료일자 중 누락 | 저장 거부, 해당 필드 오류 (BR-10) |
| SC-04-E2 | 종료일자 < 시작일자 | 저장 거부, "종료일자는 시작일자 이후" (BR-11, AC-02) |

**사후 조건 / 확인 포인트**: AC-01, AC-02 통과. 할일은 반드시 하나의 카테고리에 속한다.

### SC-05 할일 목록 조회·필터

| 항목 | 내용 |
|------|------|
| 관련 | UC-06, FR-05 / BR-15, ST-01~04, A-01, Q-05, NFR-06 |
| 우선순위 | Must |
| 화면 | 할일 목록 |
| 사전 조건 | 로그인 상태, 할일 1건 이상 |

**기본 흐름**
1. 사용자가 할일 목록을 연다 → 시스템이 본인 할일을 종료일자 오름차순(동일 시 생성일시 오름차순, Q-05)으로 표시하고, 각 항목에 상태(ST-01~04)를 표기한다. 상태는 브라우저 날짜 기준 '오늘'로 판정한다(A-01, PRD 3.2).
2. 사용자가 카테고리 1개를 선택한다 → 해당 카테고리 할일만 표시.
3. 사용자가 상태를 1개 이상 선택한다 → 카테고리 AND (상태 OR) 조건으로 표시(BR-15).
4. 결과가 한 페이지(기본 50건)를 넘으면 다음 페이지로 이동해 조회한다(NFR-06).

**대안/예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|

### SC-09 캘린더 월/주/일 조회

| 항목 | 내용 |
|------|------|
| 관련 | UC-10, FR-08 / BR-16, A-12, Q-03, NFR-06, NFR-16 |
| 우선순위 | Must |
| 화면 | 캘린더 (월/주/일) |
| 사전 조건 | 로그인 상태 |

**기본 흐름**
1. 사용자가 캘린더를 연다 → 시스템이 오늘이 포함된 월간 뷰를 표시한다(초기 뷰·날짜는 G-13).
2. 각 할일은 시작일자~종료일자의 모든 날짜 칸에 걸쳐 표시되고, 뷰 기간과 하루라도 겹치면 표시된다(BR-16). 완료 항목은 취소선 등으로 구분된다(Q-03).
3. 사용자가 주/일 뷰로 전환한다 → 주간 뷰는 일요일~토요일(A-12), 일간 뷰는 해당 날짜에 걸친 할일을 표시한다.
4. 사용자가 이전/다음을 눌러 기간을 이동한다 → 해당 기간 할일만 조회·표시한다(NFR-06).
5. 사용자가 항목을 선택한다 → 할일 편집 화면으로 이동(SC-07).

**대안/예외 흐름**

| ID | 조건 | 시스템 반응 |
|----|------|-------------|
| SC-09-A1 | 이전 달에 시작해 이번 달에 끝나는 할일 | 이번 달 칸에도 표시 (AC-05) |
| SC-09-A2 | 주의 마지막 날(토)에 시작해 다음 주까지 이어지는 할일 | 해당 주간 뷰의 토요일 칸에 표시 (AC-06) |
| SC-09-A3 | 모바일 폭에서 한 칸에 할일이 많음 | 일부만 표시하고 "+N"으로 축약. 숨긴 항목도 기간 내 모든 날짜 칸에 집계됨 (NFR-16). "+N" 선택 시 동작은 G-14 |
| SC-09-A4 | 해당 기간 할일 없음 | 빈 캘린더 표시 |

**사후 조건 / 확인 포인트**: AC-05, AC-06 통과. 캘린더 필터는 제공하지 않는다(Q-03, Should).
